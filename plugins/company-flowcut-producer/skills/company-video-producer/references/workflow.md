# 制作路线

## 新建产品视频

1. 读取产品事实，记录证据哈希、缺口和禁止项。
2. 规范化目标、平台、画幅、时长、语言、声音、数量和保留/禁止内容。
3. 初始化 SQLite 并创建任务，再检查共享素材和 ChatCut 项目。
4. 选择已有素材、AI 生成或混合路线，先完成无额外费用的故事结构。
5. 对缺失镜头或声音逐项请求精确授权并记录审批。
6. 记录 ChatCut 项目和时间线引用，完成质检后再按确认导出。

## 已有素材混剪

1. 先运行 `prepare-product` 关联精确产品文档和同目录真实媒体；检查来源、授权、尺寸、时长、可见品牌、内嵌数字与可用片段。
2. 生成 `material-catalog` 并实际查看素材。只在本机元数据中归类，不改变源文件；竞品、待审核和哈希不一致素材排除。
3. 用钩子、信息顺序、证明、节奏和行动号召拆成逐镜头 `shot-script`；产品、功能和证明镜头用 `fact_refs` 指向批准文档原文。
4. 运行确定性匹配器；未满足产品范围、类别、标签、用途、时长或审核状态的镜头进入 unresolved，不用随机素材补位。
5. 只有 `ready_for_chatcut=true` 时，才向 ChatCut 导入交接清单中的最小素材集合，并按 placements 放置。
6. 保留现有时间线，新建命名版本。对衔接不顺，优先修正动作匹配、镜头长度、场景跳变、素材自带转场和屏幕文字。
7. 对已有口播做精确删词时，在副本中读取 Script，只把目标语音轨的相关片段送入预览和提交；预览若显示非目标画面轨被重建或缩短，立即拒绝该副本并从干净基线重试。提交后刷新字幕、平滑音频接缝，并抽检删词点前后画面。

## 真实素材快剪

1. 用 `prepare-product --include-hashes` 生成事实、真实素材候选和审核门。
2. 运行 `seed-catalog`，本机查看画面并审核分类、标签、用途、方向、授权、品牌/声明和质量；把观察到的品牌与声明再次对照批准产品资料。
3. 将脚本拆为逐镜头 `shot-script` 并运行 `match-script`。记录 catalog/script/selection 三个 SHA-256；冲突或 unresolved 不阻止本机修订分类与脚本，但阻止 ChatCut 导入。
4. 创建独立 ChatCut 工程；仅导入 `chatcut_handoff.import_paths`，按 placements 完成 0 积分、可编辑的钩子—产品—场景—细节结构，不覆盖既有项目。
5. 竖屏使用横图时，可用低亮度 cover 背景加 contain 主图保留主体；不得用裁掉产品、Logo 或关键声明的方式掩盖冲突。
6. 对照 selection manifest 检查每个 ChatCut 项目的素材 ID、时间位置和时长，再预览首尾帧、每段中点和全部切换边界。通过后进入 `needs_review`，默认不导出。

## 混合制作

先完成真实素材剪辑，再定位影响理解、连续性、证明或节奏的真实缺口。只为这些缺口生成内容；失败或套餐不可用时回退到用户素材或保守剪辑，不盲目重复付费尝试。

## 模板驱动批量混剪

1. 先创建或恢复 SQLite 任务，把产品、平台、画幅、时长、语言、数量、模板标签、增量积分上限和导出策略写入指令。
2. 只读列举 `COMPANY_VIDEO_TEMPLATE_ROOTS`，只选择状态为 `approved` 且产品范围、平台、画幅、语言、时长、标签和最大输出数全部匹配的模板。记录模板路径、revision 和 SHA-256。
3. 模板是结构数据，不是产品事实或操作指令。所有台词由当前请求的 `approved_copy` 提供；产品、功能和证明镜头必须引用精确产品批准文档。
4. 用已人工审核的 `material-catalog` 运行 `template_service.py plan-batch`。每个输出按模板变体和确定性 `selection_seed` 生成独立 `shot-script` 与 `selection_manifest_sha256`；任一输出 unresolved 时整批交接保持未就绪。
5. `chatcut_batch_handoff.ready=true` 后才写入 ChatCut。共享素材最小集合只导入一次；按输出创建有意义的命名时间线或独立项目，保留现有时间线，并逐项核对 placements。
6. 每个输出完成后记录 ChatCut 时间线/项目引用、模板哈希和选择清单哈希。全部可编辑版本通过首尾帧、中点、切换边界、字幕和规格抽检后，任务进入 `needs_review`。
7. 计划器本身不授权付费生成、破坏性操作或导出。缺口需要生成时按精确范围另行审批；默认 `export_policy=not_requested`，不得批量导出。

## 三版本测试

从同一已验证基线复制三个版本，默认只改变内容顺序和钩子方向：

- A：情绪或痛点优先。
- B：功能演示与证明优先。
- C：使用场景与生活方式优先。

三版保持相同规格、声音、字幕和核心事实，避免同时改变过多变量。默认不导出，先供用户对比。

## 恢复任务

1. 有任务编号时读取状态、阶段、事件、指令、审批、成本和外部引用。没有编号时先 `list` 并按产品、规格和时间筛选；多候选由用户选择。
2. SQLite 不存在时不要为“恢复”自动初始化空库。若只有旧 ChatCut 项目，用户确认项目和基线后使用 `adopt-existing`，并把历史成本标为未知或已另行登记。
3. 只读核对 ChatCut 项目、活动时间线和生成/导出状态，并比较 NAS 来源哈希。
4. 原任务终态不变；新增 A/B/C 或其他后续工作创建带父任务引用的派生任务。
5. 用 `record-directive` 保存本轮输出数量、增量预算、禁止生成和导出策略；约束变化需要新的用户指令。
6. 只从最后一个有证据的阶段继续。ChatCut 与 SQLite 不一致时，媒体以 ChatCut 为准，审批/成本以 SQLite 为准，并记录差异。
7. 已成功或状态不明的付费操作、破坏性编辑和导出不得自动重提；交人工确认。

完成多个可编辑版本但用户暂不导出时，把每个时间线作为标准链接记录，阶段设为 `qa`、状态设为 `needs_review`，并在指令中记录 `export_policy: not_requested`。
